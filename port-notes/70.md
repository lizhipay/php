# PHP 7.0.33 backport — "Avoid state corruption via bailout"

CVE-2026-109618 (GHSA-w8hw-w9fx-j79w, OOM/bailout corruption) +
CVE-2026-109619 (GHSA-6wmf-4rv5-p3rp, stale request-global state).

- Source: php-7.0.33.tar.gz, sha256 `d71a6ecb6b13dc53fed7532a7f8f949c4044806f067502f8fb6f9facbb40452a` — **verified before extract (match)**.
- Patch: `scratchpad/patches/php-7.0.patch` (16 files, 58 hunks).
- Template: official 7.4 backport (commit 712e60f9).
- Build base image: **`btport-70`** = `debian:bullseye` (gcc 10.2.1), apt pinned to
  `archive.debian.org` (bullseye main + bullseye-security) because the default mirror
  no longer serves the bullseye point-release/security pool (404s). Native arm64, no
  `--platform` override.

## Result summary
Full port of all security-relevant changes. Two 7.4 sub-hunks dropped because the code
they touch does not exist in 7.0 (documented below). No sub-hunk with a real 7.0
equivalent was dropped. No new compiler warnings, no new crashes. The only `make test`
pass→fail deltas are the intended behaviour changes the fix itself makes (session
upload-progress neutralised; OOM fatal re-routed through `_exit`).

## Per-file adaptation notes

Straight ports (same change, context/line-numbers adapted, semantically identical):
- `Zend/zend_alloc.h` — prototype for `zend_mm_safe_error_ex` (placed before `END_EXTERN_C()`; 7.0 lacks the `zend_mm_globals_size` anchor the 7.4 hunk used).
- `Zend/zend_alloc.c` — `#include "zend_execute.h"`; add `zend_mm_safe_error_ex` (copied **verbatim** from the 7.4 patch, incl. the executing/compiling filename+lineno probe, which all exist in 7.0); rewrite `zend_mm_safe_error` to delegate to it; `zend_mm_panic`/`zend_out_of_memory` `exit(1)`→`_exit(1)`; 4 alloc-failure sites redirected (`zend_mm_alloc_heap` debug path + `_estrdup`/`_estrndup`/`zend_strndup`). 7.0 keeps its own format strings/args (e.g. `"...(%zu * %zu + %zu)", 1, length, 1`), only the called function changed.

- `Zend/zend_multiply.h` — 2 sites. `Zend/zend_strtod.c` — 2 `Balloc` sites.
- `Zend/zend_llist.c` — `zend_llist_destroy` now NULLs `head`/`tail`.
- `Zend/zend_API.h` — `array_init_singleton` macro.
- `Zend/zend_execute_API.c` — `shutdown_executor` resets (see adaptation below).
- `main/SAPI.c` — `sapi_deactivate` NULLs the 5 freed request-info pointers.
- `main/main.c` — new `max_multipart_body_parts` INI (default `-1`); `ZVAL_UNDEF(&PG(http_globals)[i])` after the dtor loop; `PG(modules_activated)=0` at end of `php_request_shutdown`.
- `main/php_variables.c` — the 4 GPC `array_init` sites → `array_init_singleton` (register_variable x3 + `php_default_treat_data` PARSE_POST/GET/COOKIE). Note 7.0 uses `zval_ptr_dtor` (not `_nogc`) in one context line.
- `main/rfc1867.c` — `php_mime_should_save_hdr` + fwd-decl; header keep/dedup rewrite in `multipart_buffer_headers`; `substring_conf` `int`→`size_t` (+ caller casts); `max_multipart_body_parts` plumbing in `rfc1867_post_handler`.

- `ext/session/session.c` — see adaptation below.

### Adaptations (semantics preserved, form changed for 7.0)

1. **`zend_new_array_singleton()` built on 7.0 primitives.** 7.4 builds it from
   `_zend_new_array_0()` (absent in 7.0). 7.0 has no `zend_new_array`; arrays come from
   `_array_init` (`ZVAL_NEW_ARR` + `_zend_hash_init`). Implemented as
   `ALLOC_HASHTABLE(ht); _zend_hash_init(ht,1,ZVAL_PTR_DTOR,0 ...); ht->nTableSize=1;`.
   Same end state as 7.4: a lazy (uninitialised) HashTable whose first real allocation
   is size 1. 7.0's `HashTable` is the modern 7.x one, `ALLOC_HASHTABLE`/`_zend_hash_init`
   exist, and `zend_hash_packed_grow` doubles from `nTableSize` (1→2→4…), so growth is
   correct. `array_init_singleton` macro = `ZVAL_ARR((arg), zend_new_array_singleton())`
   (7.0 has `ZVAL_ARR`). Verified: full build + `make test` exercises GPC/array paths.

2. **Concat overflow guards use `SIZE_MAX`, not `ZSTR_MAX_LEN`.** `ZSTR_MAX_LEN` does not
   exist in 7.0 (introduced later). 7.0's own canonical `concat_function`
   (`Zend/zend_operators.c`) guards with `op1_len > SIZE_MAX - op2_len`, so the backport
   uses the identical bound: `ZSTR_LEN(op1_str) > SIZE_MAX - ZSTR_LEN(op2_str)` (and
   `len > SIZE_MAX - ...` in the realloc branch). 7.0's inline VM concat handlers had **no**
   overflow guard at all (7.4 already had one it was merely converting), so the guard is
   *added* ahead of every `zend_string_alloc`/`zend_string_realloc` concat site, calling
   `zend_mm_safe_error_ex`. Sites: `zend_vm_def.h` 3 (1 realloc + 2 alloc),
   `zend_vm_execute.h` 27 (9 realloc + 18 alloc) = 30 total. Note 7.0 uses
   `zend_string_realloc` where 7.4 uses `zend_string_extend` in the in-place branch; the
   guard is placed identically regardless. `SIZE_MAX` compiles in the VM TU (already used
   by `zend_operators.c`); confirmed by clean build.

3. **`shutdown_executor` (CVE-2026-109619) — adapted to 7.0's structure.** 7.0's
   `shutdown_executor` has none of 7.4's `fast_shutdown` /
   `zend_objects_store_free_object_storage(&EG(objects_store), fast_shutdown)` /
   `zend_weakrefs_shutdown()` machinery, and it **already** clears the user error/exception
   handlers unconditionally (via `zval_ptr_dtor`+`ZVAL_UNDEF` and `zend_stack_clean`), so
   the 7.4 `else`-branch handler memset has no structural counterpart and its effect is
   already present. The two *novel* resets the fix introduces were added faithfully:
   - `EG(objects_store).object_buckets = NULL; EG(objects_store).top = 1;` right after
     `zend_objects_store_destroy(&EG(objects_store))` (7.0's destroy already NULLs
     `object_buckets`; `top=1` restores the "freshly-initialised" value that
     `zend_objects_store_init` uses — handle 0 reserved).
   - `EG(error_handling) = EH_NORMAL; EG(exception) = NULL;` added unconditionally at the
     very end of the function (before `EG(active)=0`), matching 7.4's unconditional
     placement (7.4 puts them right after the object-store free). In stock 7.0 these are
     only set in `init_executor` (startup), never reset at shutdown — this closes the
     between-requests window the advisory describes. All referenced fields
     (`error_handling`/`EH_NORMAL`, `exception`, `objects_store.{object_buckets,top}`)
     exist in 7.0.

4. **`session.c` neutralisation uses `|| 1` instead of `|| true`.** `true`/`false` are not
   defined anywhere in 7.0's Zend/main/TSRM (no `<stdbool.h>` pulled in; session.c never
   uses them), so `|| true` would not compile. `|| 1` is identical in effect (the callback
   always returns early). Verified by clean build.

5. **`rfc1867_post_handler` declarations hoisted.** 7.4 declares `int body_parts_limit =
   body_parts_cnt;` mid-block after an `if`. To avoid any declaration-after-statement issue
   on the older toolchain, `body_parts_cnt` and `body_parts_limit` are declared in the
   function's top declaration block (next to `upload_cnt`) and `body_parts_limit` is
   assigned after the `if (body_parts_cnt < 0)` default computation. Logic/values identical.

### Dropped sub-hunks (no equivalent code in 7.0 — nothing to change)

- **`Zend/zend_types.h` `HT_HASH_RESET`** (whole file dropped from the patch). 7.4 guarded
  its SSE2 (`__m128i`) variant against tables < 64 bytes. 7.0's `HT_HASH_RESET` is a plain
  `memset(&HT_HASH(ht, nTableMask), HT_INVALID_IDX, HT_HASH_SIZE(nTableMask))` with no SSE2
  path and no 64-byte assumption, so it is already correct for the small (singleton)
  tables this fix creates. No change needed; adding the singleton is safe as-is.
- **`Zend/zend_alloc.c` `zend_mm_alloc_huge` overflow check.** 7.4 redirects the
  `if (UNEXPECTED(new_size < size)) zend_error_noreturn(...)` guard in `zend_mm_alloc_huge`.
  7.0's `zend_mm_alloc_huge` has no such guard (the `new_size < size` check was added in a
  later release); there is no call site to redirect. The memory-limit-exhausted
  `zend_mm_safe_error(heap, "Allowed memory size...")` / `"Out of memory..."` paths in that
  same function ARE covered, via the rewritten `zend_mm_safe_error` → `zend_mm_safe_error_ex`.

Exactly **9 tests flipped pass→fail; all are intended effects of the fix**, none a port
regression (no crashes; the 8 pre-existing pristine failures — getservby*, getprotoby*,
proc_nice, DirectoryIterator getOwner, cli_process_title — are container-environment
issues and are unchanged):
- **8× `ext/session/tests/rfc1867*.phpt`** — the fix deliberately neutralises the session
  upload-progress callback (`if (!PS(rfc1867_enabled) || 1) return retval;`), so
  `$_SESSION[...upload_progress...]` is `NULL` instead of the progress array. Confirmed via
  the test `.diff` (expected array → actual `NULL`); not a crash.
- **1× `tests/lang/bug45392.phpt`** — memory-exhaustion fatal is now emitted by
  `zend_mm_safe_error_ex` (writes `"\nFatal error: … in … on line …\n"` to stderr, then
  `_exit`) instead of the old bailout path. The fatal error is still produced correctly
  (`Allowed memory size of … bytes exhausted (tried to allocate …)`); the test fails only
  because of a leading blank line vs the pre-fix `--EXPECTF--`. `zend_mm_safe_error_ex` is
  byte-for-byte the official 7.4 function, so officially-patched 7.4 produces the same
  change — this is the fix's own OOM behaviour, not a backport defect.

Gate d — **fix is present and effective** (patched binary):
- `nm sapi/cli/php | grep zend_mm_safe_error_ex` → `T zend_mm_safe_error_ex` (defined);
  count in the pristine binary = 0.
- `php -i | grep max_multipart_body_parts` → `max_multipart_body_parts => -1 => -1`
  (absent in pristine). Overridable (`-d …=2` → `ini_get` returns `2`).
- **Live multipart enforcement** (php-cgi, 4-part body): default `-1` → `PARTS_PARSED=4`;
  `-d max_multipart_body_parts=2` → `PARTS_PARSED=2` **and** error-log warning
  `Multipart body parts limit exceeded 2. To increase the limit change
  max_multipart_body_parts in php.ini.`; pristine with `-d …=2` (unknown INI) → `PARTS_PARSED=4`
  (feature genuinely new).

## Unverified / caveats
- `make test` ran on the minimal `--disable-all` config (8605 of 14880 tests actually run;
  the rest skip for missing extensions). The security-relevant paths (Zend MM/alloc, hash,
  concat VM handlers, session, rfc1867, request shutdown) are compiled and exercised. A
  fuller extension set was not built.
- No FPM SAPI was built; multipart enforcement was verified through the CGI SAPI instead,
  which exercises the same `rfc1867_post_handler` code.
- The OOM `_exit` path is validated functionally (bug45392 emits the correct fatal); the
  anti-corruption benefit (no bailout over partially-initialised state) is structural and
  not separately fuzzed.
