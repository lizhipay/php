# PHP 5.4.45 backport notes — "Avoid state corruption via bailout"

**UNOFFICIAL ANALOGY BACKPORT.** PHP 5.4 is end-of-life and received no upstream
backport of the PHP security team's fix. 5.4 uses the **old Zend engine** (old
`zend_mm` allocator, old `HashTable` with `Bucket **arBuckets`, no `zend_string`,
`TSRMLS_*` threading). This port reproduces the *defensive intent* of the official
7.4 mitigation (commit `712e60f9`, "Avoid state corruption via bailout") adapted to
5.4 idioms — it is **not** a direct diff application. Use at your own risk on EOL
servers; it has not been reviewed by upstream.

- CVEs: **CVE-2026-109618** (GHSA-w8hw-w9fx-j79w, OOM-via-bailout state corruption)
  and **CVE-2026-109619** (GHSA-6wmf-4rv5-p3rp, stale request-owned global state).
- Target: `php-5.4.45` (`https://www.php.net/distributions/php-5.4.45.tar.gz`).
- Source sha256 **verified before extraction**:
  `25bc4723955f4e352935258002af14a14a9810b491a19400d76fcdfa9d04b28f` — matched.
- Patch: `scratchpad/patches/php-5.4.patch` — applies with
  `patch -p1 --forward --batch` from the source root, no `.rej`.
- Docker image: `btport-54`.

Files touched: `Zend/zend_alloc.c`, `Zend/zend_alloc.h`, `Zend/zend_strtod.c`,
`Zend/zend_llist.c`, `ext/session/session.c`, `main/SAPI.c`, `main/main.c`,
`main/rfc1867.c` (8 files).

## MAPPED (ported, semantically identical)

| # | Site (5.4) | Change |
|---|------------|--------|
| 1 | `Zend/zend_alloc.c` `zend_mm_safe_error()` | OOM / memory-limit path no longer `zend_bailout()`s. The `zend_try{zend_error_noreturn(...)}zend_catch{}` + `zend_bailout()` tail is replaced by: free `heap->reserve` (unchanged), compute `error_filename`/`error_lineno` with the **existing** 5.4 logic (`zend_is_compiling()` / `EG(in_execution)` / `EG(active_op_array)` / `EG(opline_ptr)`), print `"\nFatal error: <msg> in <file> on line <n>\n"` to stderr, then `_exit(1)`. Mirrors upstream `zend_mm_safe_error_ex` semantics (graceful message + `_exit`). |
| 2 | new `zend_mm_safe_error_ex(const char *format, ...)` helper in `zend_alloc.c` | Added (variadic, `vsnprintf` into a 1024-byte buffer, same filename/lineno logic, `_exit(1)`). Declared `ZEND_API` and exported in `Zend/zend_alloc.h` so cross-TU callers (zend_strtod) can reach it, matching the official patch's export shape. `__attribute__((noreturn))` applied via the same GNU guard `zend_mm_panic` uses in this file. |
| 3 | `zend_alloc.c` integer-overflow guards — the 4 `safe_address()` variants (`__i386__`, `__x86_64__`, 32-bit-`HAVE_ZEND_LONG64`, generic) | `zend_error_noreturn(E_ERROR, "Possible integer overflow in memory allocation (%zu * %zu + %zu)", ...)` → `zend_mm_safe_error_ex(...)`. |
| 4 | `zend_alloc.c` `zend_mm_panic()` | `exit(1)` → `_exit(1)`. |
| 5 | `Zend/zend_strtod.c` `Balloc()` | The malloc-failure site `zend_error(E_ERROR, "Balloc() failed to allocate memory")` → `zend_mm_safe_error_ex("Balloc() failed to allocate memory")`. | 6 | `Zend/zend_llist.c` `zend_llist_destroy()` | Added `l->head = NULL; l->tail = NULL;` before `l->count = 0;` so freed list state cannot be reused. |
| 7 | `ext/session/session.c` `php_session_rfc1867_callback()` | `if (!PS(rfc1867_enabled))` → `if (!PS(rfc1867_enabled) || 1)`, neutralising the early session upload-progress producer/consumer (C89: `1`, not `true`). |
| 8 | `main/SAPI.c` `sapi_deactivate()` | After each `efree()`, NULL the field: `auth_user`, `auth_password`, `auth_digest`, `content_type_dup`, `current_user` (5.4 freed but did **not** NULL them). |
| 9 | `main/main.c` INI block | Added `PHP_INI_ENTRY("max_multipart_body_parts", "-1", PHP_INI_SYSTEM|PHP_INI_PERDIR, NULL)` after `max_file_uploads`. |
| 10 | `main/main.c` `php_request_shutdown()` | Added `PG(modules_activated) = 0;` at end of request shutdown (after the DTRACE block). |

## ADAPTED (intent kept, shape differs from 7.4 — recorded with reason)

- **`zend_mm_safe_error` rewrite vs upstream `zend_mm_safe_error_ex` delegation.**
  7.4 deletes the body and delegates to `zend_mm_safe_error_ex(format, limit, …size)`.
  In 5.4 the two functions take different argument lists (the ZEND_DEBUG
  `filename`/`lineno` extras, plus the pre-formatted memory-limit messages), so a
  variadic delegate cannot reproduce the exact `fprintf(stderr, format, limit, …)`
  call. I therefore rewrote `zend_mm_safe_error` **in place** to print and `_exit(1)`
  itself (reusing its own filename/lineno logic), and added `zend_mm_safe_error_ex`
  as the delegate used only by the fixed-format integer-overflow / Balloc sites.
  Net behaviour is identical: no `zend_bailout`, graceful stderr message, `_exit(1)`.
  `heap->overflow = 1;` is kept but is now inert (the function `_exit`s).

- **`main/main.c` `php_request_shutdown()` super-globals (CVE-2026-109619).**
  7.4 adds `ZVAL_UNDEF(&PG(http_globals)[i])` after the dtor. 5.4 has no
  `ZVAL_UNDEF` and uses `zval *` super-globals guarded by `if (PG(http_globals)[i])`.
  The faithful analogue is `PG(http_globals)[i] = NULL;` immediately after
  `zval_ptr_dtor(&PG(http_globals)[i]);` — the guard then correctly rejects the
  slot on any pre-startup access instead of dereferencing a dangling pointer.
  (Only `php_request_shutdown` is changed, matching upstream scope; the
  FastCGI-only `php_request_shutdown_for_hook` loop is left as-is.)

- **`rfc1867_post_handler` declaration placement.** 7.4 declares
  `int body_parts_limit = body_parts_cnt;` mid-function. To stay C89-clean (5.4
  compiles in gnu89 and may warn on declaration-after-statement), `body_parts_limit`
  is declared with the other locals at the top of the function and only *assigned*
  after the `post_max_size` check. Behaviour identical.

- **`multipart_buffer_headers` uses `smart_str` not `smart_string`.** 5.4's smart
  string API is `smart_str*` / `buf_value.c`; 7.4's is `smart_string*`. Mapped to the
  5.4 names. The dedup/whitelist logic is otherwise line-for-line. Verified that the
  "flush previous header on next colon" logic makes dedup correct (a kept header is
  flushed into the llist before the next header's dup lookup runs).

- **`zend_mm_safe_error_ex` is `ZEND_API` (not `static`).** The 5.x addendum
  suggested a `static` helper, but making it `ZEND_API` + declaring it in
  `zend_alloc.h` is both closer to the official patch and necessary so the
  `zend_strtod.c` Balloc site (a different translation unit) can call it. No 5.4
  caller lives in a header, so there is no include-order hazard.

## N/A (does NOT map to 5.4 — deliberately skipped, with reason)

- **`array_init_singleton` / `zend_new_array_singleton` / `HT_HASH_RESET` small-table
  guard** (`zend_API.h`, `zend_hash.c/.h`, `zend_types.h`, `main/php_variables.c`).
  5.4 uses the old `HashTable` (`Bucket **arBuckets`, no packed arrays, no SIMD
  `HT_HASH_RESET`, no `zend_string`). The 1-element over-read these guard against
  does not exist in this engine. Skipped entirely.
- **`Zend/zend_multiply.h` integer-overflow sites.** 5.4's `zend_multiply.h` is pure
  arithmetic macros (`ZEND_SIGNED_MULTIPLY_LONG`); it has **no**
  `zend_error_noreturn`/`zend_safe_address_guarded`/`zend_safe_addmult`. The multiply
  overflow guard in the old engine lives in `zend_alloc.c`'s `safe_address()` (covered
  by item 3). Nothing to change here.
- **`Zend/zend_vm_def.h` / `zend_vm_execute.h` CONCAT length checks.** The old VM's
  CONCAT has no `ZSTR_*`/`zend_string` overflow site; a tree-wide grep for
  `"Integer overflow in memory allocation"` returns **none** in 5.4. No equivalent
  edit is safe, so skipped (no guess made).
- **`Zend/zend_execute_API.c` `shutdown_executor()` user-handler / object-store
  resets.** The 7.4 fields (`EG(user_error_handler)` as `zval`, `EG(user_error_handlers)`,
  `EG(user_exception_handlers)`, `EG(objects_store).object_buckets`/`.top`,
  `zend_weakrefs_shutdown`) are 7.x constructs. 5.4's executor globals and object
  store differ fundamentally; no faithful 1:1 reset exists, and inventing field
  resets risks new bugs. Skipped (consistent with the addendum's guidance).
- **`zend_out_of_memory` / `__zend_malloc` `exit`→`_exit`.** These symbols do not
  exist in 5.4's old allocator. N/A. (Only `zend_mm_panic` exists and is handled.)
- **`main/php_variables.c` `array_init` → `array_init_singleton`.** Depends on the
  singleton HashTable primitive, which is N/A in 5.4 (see above).

## VALIDATION

**Build base:** `debian:buster` (gcc **8.3.0**), native **arm64**, no `--platform`.
PHP 5.4 does not build on modern gcc/libc; buster's gcc-8 builds it cleanly.
`debian:stretch` was not needed. buster is archived, so apt was pointed at
`archive.debian.org`.

**arm64 configure note (NOT a source hack):** PHP 5.4.45's bundled `config.guess`
(dated 2008-01-23) predates `aarch64` and fails with *"cannot guess build type"*.
Resolved with the configure flag `--build=aarch64-unknown-linux-gnu` — a standard
configure argument, no source modification. Applied identically to both trees.

Configure (both trees):
`./configure --build=aarch64-unknown-linux-gnu --disable-all --enable-cli
--enable-session --enable-ctype --enable-tokenizer --with-pcre-regex`
(`--disable-all` still builds `sapi/cli/php` and `sapi/cgi/php-cgi`; the CGI binary
was used for the real multipart POST test below.)

### (a) Patch applies cleanly
`patch -p1 --forward --batch` on a fresh tarball extraction: all 8 files patched,
**exit 0, no `.rej`/`.orig`**. Dry-run also clean.

### (b) Compile clean
Both trees `make -j8` with **0 errors**. Warning count **identical: pristine 9,
patched 9** → the patch introduces **0 new warnings**, and **none** of the 9 pre-existing
warnings are in a touched file. Patched `sapi/cli/php -v` → `PHP 5.4.45 (cli)`.

### (c) make test — pristine vs patched (NO_INTERACTION=1)

Identical results across **two** independent full runs of each tree (no flaky
variance). Total 12562 tests, 7176 executed, 5386 skipped, 1 warned in both.

| tree | passed | failed |
|------|--------|--------|
| pristine | 7128 | 17 |
| patched  | 7119 | 26 |

Delta = exactly **9** tests shift pass → fail; **0** tests fail only in pristine.
By failed-`.phpt`-path diff, the 9 new failures are **all** expected, fix-intended
behaviour changes — none is an accidental regression:

- **8 × `ext/session/tests/rfc1867*.phpt`** (`rfc1867`, `rfc1867_inter`,
  `rfc1867_sid_cookie`, `rfc1867_sid_get`, `rfc1867_sid_get_2`, `rfc1867_sid_invalid`,
  `rfc1867_sid_only_cookie`, `rfc1867_sid_post`). These assert the session
  upload-progress feature populates `$_SESSION["upload_progress_*"]`; item 7
  (`|| 1`) deliberately neutralises that producer/consumer, so `$_SESSION[...]` is
  now `NULL`. Confirmed from the `.diff` (expected `array(5){…}` → actual `NULL`).
  This IS the CVE-2026-109619 mitigation working.
- **1 × `tests/lang/bug45392.phpt`** (`ob_start()`/`ob_end_clean()` under
  `memory_limit=100`, `display_errors=stderr`). Its `--EXPECTF--` is
  `"2\nFatal error: Allowed memory size of %d bytes exhausted%s"`. The patched OOM
  path (item 1) prints `"\nFatal error: Allowed memory size …"` — with a **leading
  `\n`**, exactly like upstream's `zend_mm_safe_error_ex` — then `_exit(1)`, so the
  captured output gains one extra blank line (`.diff` shows only `002+ `). The fatal
  "Allowed memory size exhausted" message is still printed; only the leading newline
  differs. Benign, and faithful to the upstream message format (upstream updates this
  test's expectation; an EOL analogy backport does not touch tests).

No test that pristine passed newly fails for any reason **other than** these two
documented, intended consequences of the fix.

### (d) Behavioural checks (all on the patched build)

1. **INI present** — `php -i | grep max_multipart_body_parts` →
   `max_multipart_body_parts => -1 => -1`. `ini_get()` → `string(2) "-1"`.
2. **OOM path no longer bails out** — in patched `zend_mm_safe_error()`:
   `zend_bailout` occurrences = **0**, `_exit(1)` = **1**. Pristine same function:
   `zend_bailout` = **1**. The longjmp is gone; the path now `_exit`s.
3. **Helper symbol present** — `nm sapi/cli/php | grep zend_mm_safe_error_ex` →
   `… T zend_mm_safe_error_ex` (defined).
4. **Part-limit enforced (real multipart POST via `php-cgi`)** — a 5-part
   `multipart/form-data` body posted to a probe script:

   | Build | `max_multipart_body_parts` | Result |
   |-------|---------------------------|--------|
   | patched | `3` | `$_POST` has **3** keys (`f0,f1,f2`); rest rejected |
   | patched | `1` | `$_POST` has **1** key (`f0`) |
   | patched | default `-1` | `$_POST` has **5** keys (all accepted) |
   | pristine | `3` | `$_POST` has **5** keys (INI unknown → **no** enforcement) |

   The patched build truncates at exactly the limit (the `goto fileupload_done`
   fires); the default accepts normal input; the pristine build ignores the INI
   entirely — proving the enforcement is new and correct.

**Could NOT verify:** the `E_WARNING` "Multipart body parts limit exceeded" text did
not surface on the CGI output stream in my harness (warnings emitted during SAPI
POST reading appear to be discarded before the response body); the enforcement
itself is nonetheless proven by the exact part-count truncation above. The OOM
`_exit(1)` path was confirmed structurally (source + symbol + `zend_bailout` removal)
rather than by forcing a live OOM.

## SECURITY NOTE
This hardens, but does not resurrect, an EOL branch. The two root causes — longjmp
out of a half-initialised request on allocation failure, and request-owned globals
surviving into the next request — are addressed with the same strategy as upstream.
Other unrelated 5.4 EOL vulnerabilities remain unpatched; migrating off 5.4 is still
the only complete fix.
