# PHP 7.2.34 — session hardening (opt-in `session.harden`)

Source: php-7.2.34.tar.gz, sha256 `8b2777c741e83f188d3ca6d8e98ece7264acafee86787298fae57e05d0dddc78` (verified before extract).
Patch: `hardening/php-7.2-session-hardening.patch` (2 files, 7 hunks).

## What the patch does
Opt-in ini `session.harden` (bool, default `0`, `PHP_INI_SYSTEM`). Default off = stock behaviour.
When `1`: (1) every session decoder gets an empty allowed-classes set so `O:`/`C:` becomes
`__PHP_Incomplete_Class` (no `__wakeup`/`__unserialize`/`__destruct`, no autoload), killing the
`serialize_handler`-mismatch object injection; (2) `|` and `!` in the attacker-controlled
`PHP_SESSION_UPLOAD_PROGRESS` value are replaced with `_` in the stored session key.

## Mapping / adaptations vs the 8.2 reference
Same as 7.4/7.3. 7.2-specific confirmations:
- `zend_bool harden;` added after `session_vars` — 7.x has **no** `in_rfc1867_update` field.
- **No** shared unserialize-init helper: the three decoders each `PHP_VAR_UNSERIALIZE_INIT` their own
  `var_hash`; deny block applied after each of the three inits.
- `php_var_unserialize_set_allowed_classes` API present: `ext/standard/php_var.h:54`; called as
  `php_var_unserialize_set_allowed_classes(var_hash, …)`.
- MINIT differs textually from 7.3/7.4 (`zend_string_init(...)` not `zend_string_init_interned(...)`),
  but the patch anchors on `zend_class_entry ce;` which is identical, so the `ALLOC_HASHTABLE` +
  `zend_hash_init` insertion is unaffected.
- INI after `session.lazy_write`; static `php_session_no_classes`; upload_progress 5-tab loop — all at
  the 7.2 anchors.

## Build & test (Docker, gcc:10, native arm64, no --platform)
configure: `./configure --disable-all --enable-cli --enable-session --enable-tokenizer`

| Gate | Result |
|---|---|
| `patch -p1 --forward --batch` | applies, patch_rc=0, **0 .rej** |
| configure | rc=0 |
| make | rc=0, no new warnings (only the stock `mod_files.c:315 'readdir_r' is deprecated`, present in unpatched 7.2 under gcc 10 — unrelated to this patch) |
| injection `harden=0` | `harden=0 injection=FIRED` |
| injection `harden=1` | `harden=1 injection=blocked` |
| `php -i \| grep session.harden` | `session.harden => On => On` |
| scalar round-trip, harden=1 | `roundtrip u=alice n=42` |

Object-deny is the decisive gate and passes. upload_progress key sanitisation is compiled in and
gated on `PS(harden)`; it runs only during real multipart rfc1867 upload processing (not CLI-reachable),
so it is verified by compile + code review, as in the 8.2 reference.

Note: 7.2 (like all 7.0+) HAS the `php_var_unserialize_set_allowed_classes` C API, so full object-deny
applies here — this is unlike 5.4–5.6, where that API does not exist and only the upload_progress key
sanitisation (+ the ini flag) can be backported.
