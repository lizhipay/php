# session 硬化 — PHP 8.0 – 8.5

8.x 的六個版本（8.0.30 / 8.1.34 / 8.2.35 / 8.3.36 / 8.4.27 / 8.5.12）共用同一套作法，
補丁差異只在各版 `ext/session/session.c` 的錨點位置。8.2 是最初的原型與參考補丁。

## 作法（全 8.x 相同）

- `ext/session/php_session.h`：`php_ps_globals` 加 `bool harden;`。
- `ext/session/session.c`：
  - INI `session.harden`（bool、預設 0、`PHP_INI_SYSTEM`、`OnUpdateBool`）。
  - MINIT 內 `ALLOC_HASHTABLE` + `zend_hash_init(.., 0, NULL, NULL, 1)` 配置一個 process
    生命週期的空 allowed-classes 表 `php_session_no_classes`。
  - session 反序列化初始化時，若 `PS(harden)` 以
    `php_var_unserialize_set_allowed_classes(var_hash, php_session_no_classes)` 套用空表
    → 所有物件變 `__PHP_Incomplete_Class`。8.2+ 有共用 `php_session_unserialize_init()`
    helper（改一處）；8.0/8.1 的三個解碼器各自 init，於每個 init 後各插一次（故 8.0/8.1
    是 8 個 hunk，8.2+ 是 5 個）。
  - upload_progress key 於 `PS(harden)` 時把 `|`、`!` 換成 `_`。

## 驗證（Docker，native arm64，gcc-13，minimal `--disable-all --enable-cli --enable-session --enable-tokenizer`）

| 版本 | patch -p1（0 .rej） | configure/make | php -i session.harden | 注入 harden=0 | 注入 harden=1 |
|---|---|---|---|---|---|
| 8.0.30 | ✅ | ✅ 乾淨 | 有 | FIRED | **blocked** |
| 8.1.34 | ✅ | ✅ 乾淨 | 有 | FIRED | **blocked** |
| 8.2.35 | ✅ | ✅ 乾淨 | 有 | FIRED | **blocked** |
| 8.3.36 | ✅ | ✅ 乾淨 | 有 | FIRED | **blocked** |
| 8.4.27 | ✅ | ✅ 乾淨 | 有 | FIRED | **blocked** |
| 8.5.12 | ✅ | ✅ 乾淨 | 有 | FIRED | **blocked** |

注入測試：預置一個會被 `php` 解碼器當成 `key|value` 切分、於是 `unserialize` 出帶
`__wakeup` canary 的物件的 session 檔；canary 觸發＝注入成功。`harden=0` 全部 FIRED（確認
測試有效、漏洞存在），`harden=1` 全部 blocked（物件變 incomplete class，canary 不觸發）。
預設關閉（harden=0）時與原版零行為差異。

upload_progress key 的 `|`/`!` 淨化掛在 `PS(harden)` 下，與 5.x/7.x 同一份邏輯；該路徑只在
web SAPI 的 multipart 流程執行（5.x 的 note 以真實上傳驗證過淨化生效），8.x 以編譯 +
程式碼審查確認。
