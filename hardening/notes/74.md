# PHP 7.4.33 — session hardening (opt-in `session.harden`)

Source: php-7.4.33.tar.gz, sha256 `5a2337996f07c8a097e03d46263b5c98d2c8e355227756351421003bea8f463e` (verified before extract).
Patch: `hardening/php-7.4-session-hardening.patch` (2 files, 7 hunks).

## What the patch does (same intent as the 8.2.35 reference)
Opt-in ini `session.harden` (bool, default `0`, `PHP_INI_SYSTEM`). Default off = stock behaviour.
When `1`:
1. Object-deny: every session decoder gets an empty allowed-classes set, so any `O:`/`C:`
   in session data becomes `__PHP_Incomplete_Class` — no autoload, no
   `__wakeup`/`__unserialize`/`__destruct`. Kills the `serialize_handler`-mismatch object
   injection regardless of which handler wrote the data.
2. upload_progress key sanitisation: `|` and `!` in the attacker-controlled
   `PHP_SESSION_UPLOAD_PROGRESS` value (which becomes part of the stored key) are replaced
   with `_`, closing the unauthenticated delivery vector.

## Mapping / adaptations vs the 8.2 reference
| 8.2 reference | 7.4.33 |
|---|---|
| `bool harden;` in `php_ps_globals` | `zend_bool harden;` (7.x has no `bool`) |
| field added after `in_rfc1867_update` | 7.x has **no** `in_rfc1867_update` field; added after `session_vars` (last field) |
| single shared `php_session_unserialize_init()` helper sets allowed-classes once | 7.x has **no** shared helper; the three decoders (`php_serialize`, `php_binary`, `php`) each `PHP_VAR_UNSERIALIZE_INIT` their own `var_hash`. The deny block is inserted after **each** of the three inits (3 hunks). |
| `php_var_unserialize_set_allowed_classes(*var_hash, …)` | `php_var_unserialize_set_allowed_classes(var_hash, …)` — here `var_hash` is a value, not a pointer; confirmed the API exists: `ext/standard/php_var.h:53` |
| no `in_rfc1867_update` incomplete-classes line to keep | that 8.2 line is absent in 7.x, correctly dropped |
| INI entry, static `php_session_no_classes`, MINIT `ALLOC_HASHTABLE`+`zend_hash_init`, upload_progress loop | identical, placed at the 7.x anchors |

`session.harden` ini anchored after `session.lazy_write`. `OnUpdateBool` / `ALLOC_HASHTABLE` /
`zend_hash_init(ht,0,NULL,NULL,1)` all exist unchanged in 7.4. No TSRMLS needed (gone since 7.0).

## Build & test (Docker, gcc:10, native arm64, no --platform)
configure: `./configure --disable-all --enable-cli --enable-session --enable-tokenizer`

| Gate | Result |
|---|---|
| `patch -p1 --forward --batch` | applies, patch_rc=0, **0 .rej** |
| configure | rc=0 |
| make | rc=0, **no new warnings** (clean; no session/unserialize warnings) |
| injection `harden=0` | `harden=0 injection=FIRED` |
| injection `harden=1` | `harden=1 injection=blocked` |
| `php -i \| grep session.harden` | `session.harden => On => On` |
| scalar round-trip, harden=1 | `roundtrip u=alice n=42` (normal sessions unaffected) |

Object-deny is the decisive, behaviourally-proven gate and it passes. The upload_progress key
sanitisation is compiled in and wired under `PS(harden)`; it executes only inside real
multipart rfc1867 upload processing (not reachable from CLI), so it is verified by compile +
code review rather than a CLI behavioural test — same scope as the 8.2 reference.
