# PHP 7.1.33 backport notes — "Avoid state corruption via bailout"

CVE-2026-109618 (GHSA-w8hw-w9fx-j79w) + CVE-2026-109619 (GHSA-6wmf-4rv5-p3rp)
Source of truth: official 7.4 backport (commit 712e60f9). Target: php-7.1.33.

Patch file: `scratchpad/patches/php-7.1.patch` (apply from a pristine 7.1.33 tree with
`patch -p1 --forward --batch`).

Tarball verified: sha256 `0055f368ffefe51d5a4483755bd17475e88e74302c08b727952831c5b2682ea2` — matches.

## Result

Full port of the security-relevant changes. 16 of the 17 files in the 7.4 patch are
ported (incl. the VM concat overflow guards in zend_vm_def.h + zend_vm_execute.h — see
the correction note below); only zend_types.h is dropped, plus one sub-hunk of
zend_alloc.c, because the code they touch either does not exist in 7.1 or is already
correct there (details below). Both RCE mechanisms are addressed:

- CVE-109618 (OOM via bailout): every allocation-failure `zend_error_noreturn(E_ERROR, …)`
  that exists in 7.1 is redirected to the new `zend_mm_safe_error_ex()` (prints the fatal
  error and `_exit(1)`s instead of `longjmp`/`zend_bailout`); `zend_mm_panic` and
  `zend_out_of_memory` use `_exit`.
- CVE-109619 (stale global state): `shutdown_executor()` resets error/exception/user-handler
  globals and the object store; `php_request_shutdown()` UNDEFs `PG(http_globals)[i]` and
  zeroes `PG(modules_activated)`; `sapi_deactivate()` NULLs the freed auth/content-type/user
  fields; `zend_llist_destroy()` clears head/tail; the session rfc1867 progress callback is
  neutralised.
- Hardening: VM concat length-overflow guards (see below), `max_multipart_body_parts`
  INI + enforcement in `rfc1867_post_handler`, multipart header dedup/whitelist,
  `substring_conf` int→size_t, singleton GPC arrays.

### Correction — VM concat overflow guards (added after first pass)

The first revision of this port *dropped* the zend_vm_def.h / zend_vm_execute.h concat
hunks. That rationale was incomplete: while 7.1's C-API `concat_function`
(zend_operators.c) is guarded (`op1_len > SIZE_MAX - op2_len` → `zend_throw_error`), the
**VM-specialized** `ZEND_CONCAT` fast-paths call
`zend_string_extend(op1_str, len + ZSTR_LEN(op2_str), 0)` and
`zend_string_alloc(ZSTR_LEN(op1_str) + ZSTR_LEN(op2_str), 0)` with **no** overflow guard
in pristine 7.1 (e.g. zend_vm_execute.h ~4431/4436, 5319, 8516/8521, 9256). A wrapped
length sum there allocates a too-small buffer and the following `memcpy` overflows the
heap — and the allocator-level integer-overflow check does **not** catch it because the
allocation succeeds at the wrapped-small size. This is the exact site the official 7.4
patch hardens. These guards are now **ported** (moved from "dropped" to "ported").

## Build base image

`btport-71`, built **FROM debian:12** (bookworm, native arm64, gcc 12.2.0).

Rationale: the brief recommends debian:buster/bullseye for 7.0–7.3, but in this
environment the apt proxy's debian-security snapshot for bullseye/buster is stale
(404s on libc6-dev/dpkg/icu debs; base image layer newer than the mirror), so those
bases could not install build-essential. debian:12 installed cleanly and **built 7.1.33
with 0 errors and no new warnings**, so no source hacks were needed. Minimal configure:
`--disable-all --enable-cli --enable-session --enable-tokenizer --with-pcre-regex
--enable-ctype --enable-json`.

Build/test driver: `scratchpad/port-work/71/host/build_and_test.sh` (run via
`docker cp` into a container — Docker Desktop does not share the scratchpad path, so
bind mounts come up empty; cp-in/cp-out was used instead).

### make test: the 10 patched-only failures — all expected

None is a port defect. Each is either an intended behavioural consequence of the fix
(identical to what the official 7.4 patch does) or a pre-existing flaky test:

- **8 × `ext/session/tests/rfc1867*.phpt`** (rfc1867, rfc1867_inter, rfc1867_sid_cookie,
  _sid_get, _sid_get_2, _sid_invalid, _sid_only_cookie, _sid_post): the fix neutralises
  the session upload-progress callback (`if (!PS(rfc1867_enabled) || 1)` — see note on
  `true`), so `$_SESSION["upload_progress_*"]` is now `NULL` instead of the progress
  array. Verified the diff is exactly `array(5){…}` → `NULL`; the upload itself still
  succeeds and PHP does not crash. This is the documented mitigation (session upload
  progress is a confirmed RCE vector in GHSA-6wmf-4rv5-p3rp) and matches the upstream
  `ext/session/session.c` change.
- **1 × `tests/lang/bug45392.phpt`** (ob_start + memory_limit): the OOM fatal error is now
  printed by `zend_mm_safe_error_ex` (leading `\n`, written to stderr, then `_exit(1)`)
  instead of the old catchable `E_ERROR`. The message still reads
  `Fatal error: Allowed memory size of %d bytes exhausted …`; the only diff is one extra
  blank line the old EXPECTF doesn't allow. This is the core intended change of
  CVE-109618 and is identical to upstream (upstream updates this test; an EOL source-only
  backport does not ship test updates).
- **1 × `ext/standard/tests/streams/proc_open_bug69900.phpt`**: pre-existing flaky
  timing/STDIO test, unrelated to the patch (nothing in streams/proc_open is touched).
  Re-run in isolation it **fails 5/5 on the pristine tree too**; its one-off "pass" in the
  pristine full run vs "fail" in the patched full run is flakiness, not a regression.

No test that pristine passes is newly broken by a defect in the port.

## Per-file hunk mapping (adapted / dropped vs the 7.4 patch)

### Ported (semantically identical; context adapted to 7.1)

- **Zend/zend_alloc.c** — `#include "zend_execute.h"` added; new `zend_mm_safe_error_ex`
  (verbatim from 7.4); `zend_mm_safe_error` rewritten to call it; `zend_mm_panic` and
  `zend_out_of_memory` `exit(1)`→`_exit(1)`; the `alloc_heap` ZEND_DEBUG site and the three
  `_estrdup`/`_estrndup`/`zend_strndup` overflow sites redirected to `zend_mm_safe_error_ex`.
  All six helper functions it calls (`zend_is_executing`, `zend_get_executed_filename_ex`,
  `zend_get_executed_lineno`, `zend_is_compiling`, `zend_get_compiled_filename`,
  `zend_get_compiled_lineno`) exist in 7.1.
- **Zend/zend_alloc.h** — `zend_mm_safe_error_ex` prototype (anchored before `END_EXTERN_C()`;
  7.1 has no `zend_mm_globals_size` anchor line that 7.4 uses).
- **Zend/zend_hash.c** — 3 overflow sites (`zend_hash_check_size`, `zend_hash_packed_grow`,
  `zend_hash_do_resize`) → `zend_mm_safe_error_ex`; new `zend_new_array_singleton()`
  (see adaptation note).
- **Zend/zend_hash.h** — `zend_new_array_singleton` prototype.
- **Zend/zend_API.h** — `array_init_singleton` macro = `ZVAL_ARR((arg), zend_new_array_singleton())`.
- **Zend/zend_llist.c** — `zend_llist_destroy` clears `l->head`/`l->tail`.
- **Zend/zend_multiply.h** — both `zend_safe_address_guarded`/`zend_safe_addmult` overflow
  sites → `zend_mm_safe_error_ex`.
- **Zend/zend_strtod.c** — both `Balloc()` failure sites → `zend_mm_safe_error_ex`.
- **Zend/zend_execute_API.c** — `shutdown_executor` state reset (see adaptation note).
- **ext/session/session.c** — progress callback short-circuit (see `true` note).
- **main/SAPI.c** — `sapi_deactivate` NULLs auth_user/auth_password/auth_digest/
  content_type_dup/current_user after `efree`.
- **main/main.c** — `max_multipart_body_parts` INI entry; `ZVAL_UNDEF(&PG(http_globals)[i])`
  in the step-8 super-globals loop of `php_request_shutdown`; `PG(modules_activated)=0`
  after the DTRACE block.
- **main/php_variables.c** — the 4 GPC `array_init` sites (gpc_element, tmp, gpc_element_p,
  and the PARSE_POST/GET/COOKIE `&array`) → `array_init_singleton`.
- **main/rfc1867.c** — `php_mime_should_save_hdr` + forward decl of `php_mime_get_hdr_value`;
  header save loop rewritten to whitelist Content-Disposition/Content-Type and drop
  duplicates (with `isspace((unsigned char)*value)`); `substring_conf` `int len/int i`→`size_t`;
  `php_ap_getword_conf` casts; `body_parts_cnt`/`body_parts_limit` + the
  `if (--body_parts_cnt < 0) { php_error_docref(…); goto fileupload_done; }` enforcement.
- **Zend/zend_vm_def.h** — VM concat overflow guards (see adaptation note): 2 sites
  (`ZEND_CONCAT` extend branch + else-alloc branch).
- **Zend/zend_vm_execute.h** — VM concat overflow guards, generated file edited directly
  (not regenerated): 18 sites = the 9 `ZEND_CONCAT_SPEC_*` handlers × (extend + else-alloc).

### Adapted (same intent, different 7.1 implementation)

1. **`zend_new_array_singleton()` (zend_hash.c)** — 7.4 defines it as `_zend_new_array_0()`
   then `ht->nTableSize = 1`, but 7.1 has no `_zend_new_array_0`/`_zend_new_array`/
   `zend_new_array` (arrays are created via `_array_init` → `ZVAL_NEW_ARR` + `_zend_hash_init`).
   Ported with 7.1 primitives:
   `HashTable *ht = emalloc(sizeof(HashTable)); _zend_hash_init(ht, 0, ZVAL_PTR_DTOR, 0 ZEND_FILE_LINE_CC); ht->nTableSize = 1; return ht;`
   (`_zend_hash_init(…,0,…)` clamps to `HT_MIN_SIZE`=8, then we override to 1, exactly as 7.4
   does.) nTableSize=1 is safe in 7.1: `HT_HASH_RESET` is a plain `memset` and the sizing
   macros are parametric, so small tables work and grow 1→2→4→8 normally. Validated by
   `make test` — GPC/$_POST/$_GET parsing (which now uses these singleton arrays everywhere)
   passes with no new failures.
2. **`shutdown_executor` reset (zend_execute_API.c)** — 7.4 splits the resets across its
   `fast_shutdown` `if/else`, which does not exist in 7.1 (7.1 has no `fast_shutdown`,
   `zend_hash_discard`, or `zend_weakrefs_shutdown`). Ported as one unconditional block at
   the end of the function (just before `EG(active)=0;`), after every `zend_try{}` cleanup
   block, so it runs even if a bailout interrupted cleanup — the same end state as 7.4:
   `ZVAL_UNDEF(user_error_handler/user_exception_handler)`, `memset` the three user-handler
   stacks, `EG(error_handling)=EH_NORMAL`, `EG(exception)=NULL`,
   `EG(objects_store).object_buckets=NULL`, `EG(objects_store).top=1`. Placed after
   `zend_objects_store_destroy` (which `efree`s object_buckets) so there is no premature
   NULL/double-free. All referenced EG fields exist in 7.1 with the same names/types.
3. **session.c `|| true` → `|| 1`** — 7.1 has no lowercase `true` (no `<stdbool.h>` /
   `#define true`); `|| 1` is identical in effect (callback always returns immediately).
4. **VM concat overflow guards (zend_vm_def.h + zend_vm_execute.h)** — 7.4 uses
   `ZSTR_MAX_LEN`, which does not exist in 7.1, so the length-sum check uses 7.1's own
   `SIZE_MAX` idiom (the same one 7.1's `concat_function` already uses):
   - extend branch: `if (UNEXPECTED(len > SIZE_MAX - ZSTR_LEN(op2_str))) { zend_mm_safe_error_ex("Integer overflow in memory allocation"); }` before `zend_string_extend(...)`.
   - else-alloc branch: `if (UNEXPECTED(ZSTR_LEN(op1_str) > SIZE_MAX - ZSTR_LEN(op2_str))) { zend_mm_safe_error_ex(...); }` before `zend_string_alloc(...)`.
   Guarded set matches upstream exactly: the `ZEND_CONCAT` extend + else-alloc branches
   only. **Counts: 2 in zend_vm_def.h + 18 in zend_vm_execute.h = 20.** This is fewer than
   7.2's 4 + 36 for a real structural reason, not an omission: in 7.1 `ZEND_FAST_CONCAT`
   has **only** the flat slow-path alloc (no op1-reuse fast path — the first revision
   confirmed 0 `zend_string_extend` sites in any FAST_CONCAT handler), which is exactly the
   branch upstream 7.4 leaves **unguarded** (7.4 flat slow-path, vm_def.h line ~3280). So
   every 7.1 FAST_CONCAT is the unguarded-upstream case and correctly receives no guard;
   only the `ZEND_CONCAT` family (which in 7.1 has both extend + else branches) is guarded.
   The generated `zend_vm_execute.h` was edited directly (never regenerated), using a script
   that inserts the extend guard before every `zend_string_extend(op1_str, len + …)` (all 9
   are CONCAT) and the else guard before every `zend_string_alloc(ZSTR_LEN(op1_str) + …)`
   whose immediately preceding non-blank line is `} else {` (the 9 CONCAT else branches);
   FAST_CONCAT's flat allocs (2-tab indent, not preceded by `} else {`) are skipped.
   Behavioural presence confirmed: the `"Integer overflow in memory allocation"` literal is
   in the patched binary (count 1, deduped) and absent from pristine (count 0).

### Dropped (not present / not applicable in 7.1) — no security loss

1. **zend_alloc.c `zend_mm_alloc_huge` overflow check** — 7.4 converts a pre-existing
   `if (new_size < size) zend_error_noreturn(…)` guard in `zend_mm_alloc_huge`. 7.1's
   `zend_mm_alloc_huge` has **no such guard**, so there is no site to redirect. The 7.4 patch
   only *converts* this guard (does not introduce it); adding one to 7.1 would be a new
   behaviour beyond the patch, so it is dropped. Any real allocation overflow in 7.1 still
   reaches `zend_mm_safe_error_ex` via the ported `zend_safe_address_guarded`/alloc sites.
2. **zend_types.h `HT_HASH_RESET`** — 7.4 adds a `size < 64` `memset` fallback to its
   **SSE2-intrinsic** `HT_HASH_RESET`. 7.1 has no SSE2 variant at all; its `HT_HASH_RESET`
   is already `memset(&HT_HASH(ht, nTableMask), HT_INVALID_IDX, HT_HASH_SIZE(nTableMask))`,
   which is already correct for small (incl. size-1 singleton) tables. Nothing to change.
3. **FAST_CONCAT flat slow-path allocs (within zend_vm_def.h + zend_vm_execute.h)** — NOT a
   dropped file, but the one concat branch intentionally left unguarded, matching upstream
   7.4 (which leaves its FAST_CONCAT flat slow-path alloc, vm_def.h ~line 3280, unguarded).
   In 7.1 this is the *only* alloc FAST_CONCAT has. See adaptation note #4 for the full
   rationale; the `ZEND_CONCAT` concat guards themselves are ported.

(An earlier revision of this port dropped the whole concat family on the mistaken grounds
that `concat_function`'s guard covered it; see the "Correction" note near the top. The VM
fast-paths were in fact unguarded in pristine 7.1 and are now guarded.)

## Unverified / caveats

- **FPM / mod_php not exercised.** Testing was CLI + the built-in web server (minimal
  `--disable-all` build). The part-limit enforcement was verified functionally over HTTP via
  the built-in server; the `php_error_docref` "Multipart body parts limit exceeded" warning
  text was not captured in the server stderr log in that run (likely routed to the request
  error context), but the security-relevant effect — parsing truncates at the limit (5→2
  parts) — is confirmed. A real OOM `_exit` and the mod_php/FPM shutdown-ordering paths were
  not driven end-to-end; they are verified only by source inspection + symbol presence.
- **Toolchain differs from the brief's suggestion** (debian:12/gcc-12 rather than
  buster/bullseye) due to the stale apt mirror; the build was clean (0 errors, no new
  warnings) so this is not believed to affect correctness, but the exact binary differs from
  a period-correct toolchain build.
- nTableSize=1 singleton arrays in 7.1 are reasoned-safe and pass the full test suite, but
  7.1's hashtable internals are older than 7.4's; no dedicated stress test of pathological
  nested-array growth was run beyond `make test` coverage.
- **VM concat overflow guards not runtime-triggered.** Hitting the guard needs a string
  whose length is within `SIZE_MAX` of overflow (effectively ~`SIZE_MAX` bytes), which
  cannot be allocated, so the overflow branch can't be exercised at runtime. Verified by:
  source (20 guard sites, correct `len`/`op1_str` operands and `SIZE_MAX` bound), clean
  compile (0 errors/warnings in the VM files), and binary presence (`strings` shows the
  guard's error literal in the patched binary, count 1, absent from pristine). The guard
  logic mirrors 7.1's own `concat_function` `SIZE_MAX` check, which `make test` exercises.
