# PHP 5.4.45 — session hardening (`session.harden`)

## allowed_classes C API — ABSENT (object-deny is N/A for 5.x)
`grep php_var_unserialize_set_allowed_classes ext/standard/php_var.h` → **no match**
(confirmed on the pristine 5.4.45 tree).

No allowed-classes C API exists in PHP 5.x (no 8.x/7.1 setter, no 7.0
`php_var_unserialize_ex(..., HashTable *classes)`). The 5.4 `php_var_unserialize()`
takes no class list, so the object-deny half of the 8.2 hardening **cannot be
implemented** here.

Therefore the serialize_handler-mismatch **object-injection RCE is NOT neutralised
by this patch on 5.4**; the injection test still FIRES at `session.harden=1`
(expected, documented). On 5.x that defense is config-layer (don't store objects
in sessions / pin one `session.serialize_handler`); this patch only closes the
unauthenticated upload_progress **delivery vector**.

## What mapped from 8.2 → 5.4
| 8.2 reference | 5.4 implementation |
|---|---|
| `bool harden;` in `php_ps_globals` | `zend_bool harden;` — **5.4 has no `use_strict_mode`** (added 5.5.2), so the field is placed after the last field `rfc1867_min_freq`, before the struct close |
| INI `session.harden` `PHP_INI_SYSTEM` `OnUpdateBool` | identical bytes, but — no `session.use_strict_mode` entry in 5.4 — it is placed after `session.use_only_cookies` instead |
| `static HashTable *php_session_no_classes` + MINIT alloc | **omitted — N/A** (no allowed-classes API in 5.x) |
| set empty allowed-classes on var_hash before unserialize | **omitted — N/A** (object-deny not available) |
| upload_progress key `\|`/`!` → `_` under `PS(harden)` | implemented; 5.x `smart_str` uses `.c` / `.len` (`size_t`), loop over `progress->key.c` right after `smart_str_0(&progress->key)` |

Notes:
- Only structural difference vs 5.5/5.6 is the missing `use_strict_mode`, which
  shifts the struct- and INI-anchor lines; the added code itself is identical.
- `smart_str` shape identical to 5.5/5.6. `harden=0` is byte-for-byte stock
  behaviour (default-off no-op).

## Build (Docker, native arm64, no --platform)
- Base image `btport-54` (Debian 10 buster, gcc 8.3.0, aarch64).
- `./configure --build=aarch64-unknown-linux-gnu --disable-all --enable-cli --enable-session CFLAGS="-O2 -g -fno-strict-aliasing"`
- `--build=aarch64-unknown-linux-gnu` is **required**: 5.4.45 ships a 2008-era
  `config.guess` that cannot auto-detect aarch64 (`cannot guess build type`). Same
  flag the CVE backport used for 5.4. 5.5/5.6 do not need it.
- Patch sha256: `27935227e7f8d2b9285af3ee52da95ab0fc545b265848eb28fddb8d975a7fe5a`

## upload_progress key sanitisation — verified at runtime (decisive gate for 5.x)
Real multipart upload against the CLI built-in web server (`php -S`, present in
5.4+), `session.upload_progress.enabled=1`, `cleanup=0`,
`serialize_handler=php_binary`, posting `PHP_SESSION_UPLOAD_PROGRESS=evil|name!x`:

| | stored session key |
|---|---|
| `session.harden=0` | `upload_progress_evil\|name!x` — raw `\|` and `!` present |
| `session.harden=1` | `upload_progress_evil_name_x` — `\|` and `!` replaced by `_`; no raw delimiter present |

Delivery-vector sanitisation confirmed working on 5.4. Object-deny is N/A and is
not (cannot be) verified — see top of file.
