# PHP 5.6.40 — session hardening (`session.harden`)

## allowed_classes C API — ABSENT (object-deny is N/A for 5.x)
`grep php_var_unserialize_set_allowed_classes ext/standard/php_var.h` → **no match**
(confirmed on the pristine 5.6.40 tree).

There is **no allowed-classes C API anywhere in PHP 5.x** — neither the
`php_var_unserialize_set_allowed_classes()` setter (8.x / 7.1+) nor the
`php_var_unserialize_ex(..., HashTable *classes)` variant (7.0). The 5.x
`php_var_unserialize()` has no `classes` parameter at all, and
`var_unserializer.re` has no class-allow gate. So the object-deny half of the
8.2 hardening **cannot be implemented** on 5.6 at the C level.

Consequently the serialize_handler-mismatch **object-injection RCE is NOT
neutralised by this patch on 5.6**. The injection test still FIRES at
`session.harden=1` (see gate results) — this is expected and documented. On 5.x
the object-injection defense belongs at the config layer (do not store objects in
sessions / pin a single `session.serialize_handler`); this patch only closes the
unauthenticated **delivery vector** via the upload_progress key sanitisation.

## What mapped from 8.2 → 5.6
| 8.2 reference | 5.6 implementation |
|---|---|
| `bool harden;` in `php_ps_globals` | `zend_bool harden;` (added after `use_strict_mode`, before `session_data_hash[16]`) |
| INI `session.harden` `PHP_INI_SYSTEM` `OnUpdateBool` | identical (placed after `session.use_strict_mode`) |
| `static HashTable *php_session_no_classes` + MINIT alloc | **omitted — N/A** (no allowed-classes API in 5.x) |
| set empty allowed-classes on var_hash before unserialize | **omitted — N/A** (object-deny not available) |
| upload_progress key `\|`/`!` → `_` under `PS(harden)` | implemented; 5.x `smart_str` uses `.c` / `.len` (`size_t`), loop over `progress->key.c` right after `smart_str_0(&progress->key)` |

Notes:
- 5.x `smart_str` is `{ char *c; size_t len; size_t a; }` — the sanitisation uses
  `char *hk = progress->key.c; size_t hl = progress->key.len;` (not the 8.x
  `ZSTR_VAL`/`ZSTR_LEN`). `size_t` is used to avoid a signedness warning.
- `harden=0` leaves every code path byte-for-byte identical to stock → default-off
  is a true no-op.

## upload_progress key sanitisation — verified at runtime (decisive gate for 5.x)
Driven with a real multipart upload against the CLI built-in web server
(`php -S`, which runs the rfc1867 parser), `session.upload_progress.enabled=1`,
`cleanup=0`, `serialize_handler=php_binary` (stores the key length-prefixed so
`\|` and `!` survive literally), posting a `PHP_SESSION_UPLOAD_PROGRESS` value of
`evil|name!x`:

| | stored session key |
|---|---|
| `session.harden=0` | `upload_progress_evil\|name!x` — raw `\|` and `!` present |
| `session.harden=1` | `upload_progress_evil_name_x` — `\|` and `!` replaced by `_`; no raw delimiter present |

So the delivery-vector sanitisation is confirmed working on 5.6. The object-deny
part is N/A and is not (and cannot be) verified — see top of file.
