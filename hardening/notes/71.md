# PHP 7.1.33 — session hardening (`session.harden`)

## allowed_classes C API
**Present.** `grep php_var_unserialize_set_allowed_classes ext/standard/php_var.h`
→ `PHPAPI void php_var_unserialize_set_allowed_classes(php_unserialize_data_t d, HashTable *classes);`
Full object-deny applies, same mechanism as the proven 8.2.35 reference.

## What mapped from 8.2 → 7.1
| 8.2 reference | 7.1 implementation |
|---|---|
| `bool harden;` in `php_ps_globals` | `zend_bool harden;` (7.x has no `bool`) |
| INI `STD_PHP_INI_BOOLEAN("session.harden","0",PHP_INI_SYSTEM,OnUpdateBool,...)` | identical |
| `static HashTable *php_session_no_classes` + alloc in MINIT | identical |
| set empty allowed-classes in the shared `php_session_unserialize_init()` | **no shared helper in 7.1** — each of the 3 decoders (`php_serialize`, `php_binary`, `php`) calls `PHP_VAR_UNSERIALIZE_INIT` inline, so the `php_var_unserialize_set_allowed_classes(var_hash, php_session_no_classes)` guard was added after each of the 3 inits |
| upload_progress key `\|`/`!` → `_` under `PS(harden)` | identical bytes |

Notes:
- 7.1 has no `in_rfc1867_update` field / `php_var_unserialize_set_incomplete_classes_only()` (those are 8.x); that branch is simply absent here.
- `harden=0` leaves `var_hash->allowed_classes` NULL (default from `ecalloc`), so behaviour is byte-for-byte stock PHP. Default off.

- `./configure --disable-all --enable-cli --enable-session --enable-tokenizer`

| Gate | Result |

## upload_progress key sanitisation
Implemented identically to the proven 8.2 patch (same bytes). Not exercised at
runtime: the rfc1867 multipart-upload path only fires in web SAPIs (fpm/cgi), not
in the CLI SAPI used for the build gate, so it is verified by code-identity with
the 8.2 reference rather than a CLI run. The decisive runtime gate for 7.1 is the
object-injection test above, which passes.
