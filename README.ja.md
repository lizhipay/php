# PHP セキュリティ更新

**PHP の重大な RCE 脆弱性（CVE-2026-109618 / CVE-2026-109619）をワンコマンドで修正。** サーバー上のすべての PHP（BaoTa/aaPanel、ソースビルド、ディストリのパッケージ）を自動検出し、それぞれ適切な方法で修正します。公式のバックポートが出なかった EOL バージョンには、ソースレベルの移植パッチを提供します。

## 脆弱性について

2026-10-21、PHP プロジェクトは CVSS 9.2 の重大な脆弱性 2 件を公表しました。**認証なしでのリモートコード実行（RCE）** が可能で、Web リクエストを処理するすべての PHP（PHP-FPM、Apache mod_php、php-cgi、FrankenPHP、LiteSpeed）が影響を受けます。

- アドバイザリ: <https://www.php.net/archive/2026.php#2026-10-21-5>
- `CVE-2026-109618`（GHSA-w8hw-w9fx-j79w）: メモリ不足時に PHP が半初期化状態のリクエストから `longjmp` で抜け、シャットダウン処理がその不正な状態を扱ってしまう。
- `CVE-2026-109619`（GHSA-6wmf-4rv5-p3rp）: リクエスト固有のグローバル状態が次のリクエストまで残り、通常の初期化前に読まれる（use-after-free）。

**完全な対策は修正済み PHP への更新のみです。** 本リポジトリはそれをワンコマンドで行い、公式バックポートが出なかった旧バージョンにはソースレベルのパッチを提供します。

## ワンコマンド修正

サーバーで root として実行:

```bash
curl -fsSL https://raw.githubusercontent.com/lizhipay/php/main/php-security-update.sh -o php-security-update.sh && bash php-security-update.sh
```

**サーバー上のすべての PHP を自動検出**し（BaoTa に限りません）、インストール元とバージョンごとに処理します:

| インストール元 | 処理 |
|---|---|
| BaoTa / aaPanel（`/www/server/php/*`） | 自動で再コンパイル＋パッチ適用 |
| ソースビルド（`/usr/local`、`/opt`、LiteSpeed lsphp、PATH 上の php-fpm） | 自動で再コンパイル＋パッチ適用 |
| ディストリのパッケージ（apt / yum の php-fpm） | **案内のみ**——パッケージマネージャで更新（ディストリに修正あり）。再コンパイルはしない |

| バージョン | 処理 |
|---|---|
| 8.2 / 8.3 / 8.4 / 8.5 | 同系列の最新修正版へアップグレード |
| 7.4 / 8.0 / 8.1 | 系列最終版＋**PHP 公式**のバックポートを適用して再コンパイル |
| 7.0 / 7.1 / 7.2 / 7.3 | 系列最終版＋**本リポジトリの移植**パッチを適用して再コンパイル |
| 5.4 / 5.5 / 5.6 | 系列最終版＋**本リポジトリの移植**パッチを適用して再コンパイル |
| 5.2 / 5.3 以前 | 公式の緩和設定のみ適用 |

主なオプション:

```bash
bash php-security-update.sh --check      # 計画の表示のみ、変更しない
bash php-security-update.sh --only 74,82 # 指定バージョンのみ（バージョン番号またはインストール ID）
bash php-security-update.sh -y           # カウントダウンなしで即開始
```

### 安全設計

- 各バージョンは置き換え**前**にコンパイルと検査を行い、**先にフルバックアップ**を取得。起動検証に失敗すると**自動でロールバック**——サイトは FPM 再起動時の約 1〜2 秒だけ途切れます。
- すべてのソースは**SHA256 検証**後に使用。パッチはスクリプトに埋め込まれ自己検証されます。
- 元の configure フラグとコンパイラを再利用するため、拡張モジュールは元のビルドと一致します。
- PHP-FPM の再起動はサービスマネージャがあればそれを使い、なければ `SIGUSR2` によるグレースフルリロード。どちらも不可なら手動再起動を案内します（推測はしません）。
- ディストリのパッケージ PHP には一切触れず、パッケージ更新コマンドを表示するのみ（公式の案内に準拠）。

## ソースパッチ

PHP チームがバックポートを出したのは 7.4 / 8.0 / 8.1 のみで、より古いバージョンには何もありません。`patches/` に単体で使えるパッチがあります:

- `php-7.4.patch`、`php-8.0.patch`、`php-8.1.patch` —— **公式**の PHP バックポート（上流コミット付き、そのまま保存）。
- `php-7.0.patch` … `php-7.3.patch`、`php-5.4.patch` … `php-5.6.patch` —— 公式修正のロジックに倣って旧バージョンへ移植したもの。

> 旧バージョンの移植パッチは**非公式**でベンダーのレビューは受けていませんが、各バージョンを Docker で実際にコンパイルし、PHP 公式テストスイートを適用前後で比較してリグレッションがないことを確認しています。各バージョンの変更メモと検証数値は `port-notes/`、バージョン横断の整合性チェックは `port-notes/AUDIT-concat-guards.md` にあります。

単一パッチの手動適用:

```bash
cd php-7.3.33
patch -p1 < /path/to/php-7.3.patch
./configure ... && make && make install
```

## 構成

```
php-security-update.sh   ワンコマンド修正スクリプト（全パッチ埋め込み済み、そのまま配布可）
patches/                 バージョン別の単体パッチ（公式 3 + 移植 7）
src/                     スクリプトのテンプレートとビルダー（build.sh が patches/ を埋め込む）
port-notes/              各旧バージョンの変更メモ、検証データ、横断チェック
docs/                    脆弱性と修正に関する技術メモ
```

パッチやテンプレートを編集した後にスクリプトを再ビルド:

```bash
bash src/build.sh ./php-security-update.sh
```

## 適用範囲と免責事項

Linux のみ。ソース再コンパイルには動作するツールチェーンと、PHP ソース取得のためのインターネット接続が必要です（SHA256 検証済み）。旧バージョン（7.0-7.3、5.4-5.6）のパッチは非公式の移植で、現状のまま提供されます。本番環境ではまず `--check` で計画を確認し、オフピーク時間帯に実行してください（スクリプトはバックアップと自動復旧を行います）。恒久的な対策は、これらのサイトをサポート対象の PHP バージョンへ移行することです。
